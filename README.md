# MailNest

自托管邮件收发系统，使用 React / TypeScript 前端、Fastify / TypeScript 后端和 SQLite。可接入 Gmail OAuth 2.0 或 IMAP / SMTP 邮箱，统一查看多个邮箱，也可按账号单独管理。支持手机、平板和桌面布局、PWA 安装、邮件提醒和独立 API 令牌。

当前 NAS 的正式访问地址为 <https://mail.leixin.me>，由现有反向代理提供 HTTPS。浏览器登录、PWA 安装和 Google 授权均使用此域名；`http://192.168.91.85:5173` 仅作为反向代理后端和健康检查地址。服务管理及来源配置说明见 [NAS 访问与管理](docs/local-access.md)。运行此服务时，默认开发端口 5173 已占用。

## 本地开发

需要 Node.js 24+ 和 npm。所有命令在项目根目录执行：

```sh
cd /volume2/workspace/mailnest
npm install
npm run init
npm run dev
```

访问 <http://localhost:5173>。初始化脚本创建权限为 `0600` 的 `.env`，生成随机登录密码、邮件凭据加密密钥和 Web Push VAPID 密钥，并仅首次显示初始密码；已有 `.env` 不会被覆盖。登录邮箱默认 `admin@example.com`，首次启动前可修改 `.env` 中的 `ADMIN_EMAIL` / `ADMIN_NAME`。数据库已有用户后，修改初始化环境变量不会重置用户；在设置中修改密码。

后端监听 `127.0.0.1:3001`，Vite 将 `/api` 代理至后端。浏览器应从同一个前端地址访问，地址必须与 `APP_URL` 一致（`localhost` 与 `127.0.0.1` 为不同来源）。`DATA_DIR=./data` 总是相对项目根目录解析。

## 接入邮箱

在设置中添加邮箱，或配置 Google OAuth 后点击连接 Gmail。普通 IMAP / SMTP 使用邮箱服务商提供的地址、端口和应用专用密码，支持 IMAP 和 SMTP 使用不同用户名 / 密码。添加时会验证收发连接，秘密加密保存且不返回浏览器。Gmail 详见 [Gmail 配置](docs/gmail.md)。

左侧按“所有邮箱”和每个已连接邮箱分别显示独立的文件夹列表，可折叠各分组。每次打开或刷新页面，“所有邮箱”默认展开，各账号默认折叠；侧栏顶部直接显示写邮件按钮。合并列表按收件箱、草稿、已发送、垃圾邮件、已删除、归档及重要目录的用途汇总，各账号使用服务商真实目录路径；自定义文件夹仅显示在所属账号下。目录来自同步缓存，空目录也可查看，不能选择的容器不作为邮件列表打开。切换范围会清空搜索、回到第一页并关闭当前邮件，避免旧条件带到另一个邮箱。

在“设置 → 邮箱管理”点击邮箱卡片的编辑按钮，可修改名称、颜色、服务器、端口、加密方式及登录凭据。密码不回填，留空保留原凭据；连接配置验证成功后才保存，失败可直接修改并重试。Google OAuth 邮箱可修改名称和颜色，或重新授权。更改邮箱地址、IMAP 主机或登录用户名后会重建该账号的本地缓存并重新同步，远端邮件保留；修改密码、SMTP 或显示信息不清理邮件缓存。

邮件列表支持统一收件箱、单账号筛选、未读 / 星标、搜索、已发送 / 归档 / 回收站，支持阅读、回复、转发、发信和附件。标记、归档、移入回收站会同步到远端邮箱；删除账号只移除本地连接与缓存，不删除邮箱服务商中的邮件。

界面使用简约的冷灰 / 蓝色液态玻璃风格，侧栏、工具按钮和弹窗采用透明层、细边与柔和高光，邮件列表和阅读区保持纯白背景。字体使用系统字体，未读、选中、星标和焦点分别保留清晰状态；不支持背景模糊或系统要求减少透明度时使用不透明背景。

桌面宽屏参照 Apple Mail 使用邮箱导航、邮件列表、阅读区三栏；拖动两条分隔线可调整宽度，浏览器会记住设置，双击分隔线恢复该栏默认宽度。分隔线也支持左右方向键（Shift 加快）、Home / End。邮件列表独立滚动，打开或关闭邮件保留列表位置；窗口缩小时自动给阅读区留出空间，再扩大时恢复偏好宽度。平板窄屏与手机自动切换单独列表 / 阅读视图，长主题与摘要截断显示，星标保留便于触按的按钮区域。顶部采用按列对齐的紧凑工具栏，回复、转发、删除和标记集中在一行；标记菜单提供已读 / 未读与星标，更多菜单提供归档、移回收件箱等操作。阅读区较窄时安装和提醒入口收进更多菜单，搜索与同步继续可用。发件人、主题、收件人采用三行信息，展开收件人可查看完整地址、抄送、主题及日期。顶部的文件夹、邮件数量和操作栏固定，邮件信息与正文在下方滚动，打开另一封邮件从顶部开始，手机底部导航保持可用。同步、轮询与新邮件事件更新时保留已有列表和滚动位置；刷新失败会保留上次列表并提供重试，切换目录 / 搜索 / 分页时按新范围加载。

正文默认底色与系统阅读区一致，邮件内部指定的卡片与品牌背景保留。HTML 正文保留邮件自己的字体、颜色、内联样式、样式表、卡片和按钮排版，图片自动加载，宽表格在正文内横向滚动。邮件内容放在无同源权限的沙箱与独立样式范围中，脚本、事件、表单与外部样式表不执行；CSS 仅保留排版规则，过滤导入、危险属性与资源地址，不让邮件改变应用界面。正文按实际内容高度展示，图片加载或栏宽变化后重新测量。

转发默认使用原邮件所属邮箱，收件人留空，主题及原文引用可编辑；HTML 原文转为纯文本引用。原附件可移除，点击发送时才载入，读取失败保留草稿供重试；新加附件与原附件合计最多 20 个、20 MiB。回复保留邮件线程头，转发建立新线程。正文被截断时会在转发窗口提示。

默认每 60 秒同步每个可选文件夹最近 200 封邮件摘要，每账号最多 100 个文件夹；通过 `SYNC_INTERVAL_SECONDS`（30–86400 秒）和 `SYNC_MESSAGE_LIMIT`（20–1000 封）配置。正文和附件在打开邮件时加载，完整邮件超过 30 MiB 需使用原邮箱客户端查看。列表、分页和搜索针对缓存主题、发件人及已加载正文；账号未读数来自远端完整收件箱，可能大于缓存列表中的未读数。当前版本不提供整个远端历史邮箱的完整索引。SMTP 发送成功后尽力保存已发送副本，保存失败会返回警告，避免用户误以为发送失败而重复发送。

## 构建与运行

开发默认地址为 `http://localhost:5173`。本机运行构建产物时先修改 `.env`：

```dotenv
NODE_ENV=production
APP_URL=http://localhost:3001
GOOGLE_REDIRECT_URI=http://localhost:3001/api/v1/oauth/google/callback
```

然后执行：

```sh
npm run build
npm start
```

此时后端直接提供前端页面，访问 <http://localhost:3001>。生产模式仅允许回环地址使用 HTTP；公网必须配置 HTTPS。

Docker 本机运行也使用上述 `.env` 地址，默认仅绑定宿主机 `127.0.0.1:3001`：

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 mailnest
```

基础 Docker 配置将数据库存于持久卷 `mailnest_data`，应用以非 root 用户运行。当前 NAS 使用 `/volume2/docker/mailnest` 和 `deploy/compose.nas.yml` 模板，数据绑定至该目录的 `data/`，现有反向代理将 <https://mail.leixin.me> 转发到 NAS 的 HTTP 5173 端口。部署目录 `.env` 使用 `NODE_ENV=production`、`APP_URL=https://mail.leixin.me`、`GOOGLE_REDIRECT_URI=https://mail.leixin.me/api/v1/oauth/google/callback`、`TRUST_PROXY=true`。修改这些环境变量后执行 `docker compose up -d --force-recreate mailnest`，单独 `restart` 不会加载新的容器环境。管理命令见 [NAS 说明](docs/local-access.md)，现有代理、独立 Caddy 模板及备份步骤见 [部署文档](docs/deployment.md)。

## PWA 与提醒

点击页面顶部的“安装应用”，或进入“设置 → 应用与提醒”安装。在支持的浏览器提供安装事件后，按钮会触发系统安装窗口；其他情况下会显示对应设备的操作指引。取消或安装窗口失败后可再次查看指引，从独立应用打开时显示“已安装”。

完整 PWA 安装和推送提醒需要 HTTPS；`localhost` 可供本机测试。当前 NAS 请从 <https://mail.leixin.me> 打开页面并安装应用。旧 HTTP IP 地址上的快捷方式应改为此域名，HTTP 后端地址不用于浏览器登录、PWA 或后台推送。安装按钮不能绕过浏览器的安全要求。[MDN 安装要求](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)

Android / 桌面可使用浏览器安装菜单；iPhone / iPad 可在 Safari 的分享菜单选择“添加到主屏幕”。启用通知需要用户主动授权，iOS / iPadOS 16.4+ 的 Web Push 要从主屏幕应用内启用。[WebKit 官方说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

提醒由定时同步发现新邮件触发，默认每 60 秒轮询，并非即时 IMAP 通知；登录后可从 `/api/v1/config` 的 `pollingInterval` 验证间隔。INBOX 首次成功同步及 UIDVALIDITY 重置时建立安静基线，之后发现的新到邮件会提醒，包括已被其他客户端先读过的邮件；未读角标仍按真实未读数计算。

页面打开时通过 SSE 接收同步 / 新邮件事件，后台通过 Web Push 提醒。同一批前台与后台提醒共用 `notificationId`，由 Service Worker 去重；同账号使用稳定通知 tag，新一批通过 `renotify` 再次提醒。去重用 IndexedDB 仅保存不含业务内容的 UUID 和时间，保留 7 天、最多 128 条，不保存正文或凭据。历史读取和写入各有 500 毫秒上限，操作失败或挂起时降级为内存，不会一直阻塞通知队列。Service Worker 只缓存应用静态资源，不缓存登录后的邮件 API 或附件；离线页面不提供邮件收发。

推送订阅不拦截 DNS / IP 地址，沿用运行环境的 TUN / 代理连接。登录、回到前台、网络恢复或 Service Worker 切换时，会自动补登记已有且与当前 VAPID 公钥匹配的订阅；不会自动创建订阅或申请通知许可。公钥变更时需在“设置 → 应用与提醒”重新开启，服务端确认登记后才显示已开启。应用启动会观察已安装中或等待中的 Worker；回到前台和网络恢复时检查更新，不强制重载正在阅读或编辑的页面。实际送达受浏览器、系统通知权限和网络影响。

在“设置 → 应用与提醒”开启本设备后台提醒后，可点击“发送测试通知”，与新邮件均带通知 UUID，走相同的 Worker 展示 / 去重链路；服务器统一使用高优先级、1 小时有效期和 aes128gcm 加密。成功提示表示推送服务已接受请求，请同时检查设备系统通知；仅测试当前设备，每 15 秒最多一次，过期订阅需重新开启。测试不会增加未读邮件数。

当前用户已确认设备能收到测试通知，自动新邮件的真机送达仍待验收。排查时可查看服务器日志的 `New-mail push accepted` / `New-mail push failed`；日志不包含 endpoint、订阅密钥或邮件正文，accepted 也不表示设备已送达。

应用内提醒铃铛和手机收件箱显示总未读数字红点；较窄阅读区的铃铛收起时，“更多”按钮及提醒菜单保留数字（超过 99 显示 99+），页面标题显示总未读数；与当前筛选、搜索或账号无关，数据口径为所有账号远端收件箱的未读数之和。支持 Badging API 的已安装应用同步系统图标数字，后台推送也携带真实总未读数；清零与退出登录清除角标。iOS / iPadOS 16.4+ 主屏幕应用的角标受通知权限控制，Android 桌面红点或数字由系统通知 / 启动器支持决定。[WebKit 角标说明](https://webkit.org/blog/14112/badging-for-home-screen-web-apps/)、[Chrome 平台说明](https://developer.chrome.com/docs/capabilities/web-apis/badging-api)

## API 与维护

版本化接口统一使用 `/api/v1`。网页登录使用 HttpOnly 会话 Cookie；第三方应用可在设置中创建独立 Bearer 令牌。API 令牌仅显示一次，可随时撤销；修改密码会撤销全部会话与 API 令牌，需要重新登录并重新生成令牌。本系统按个人单人使用设计，不提供注册、用户切换或用户管理界面。侧栏底部只保留一个设置入口；登录密码、API 令牌及退出登录统一在设置中管理。首次启动由环境变量创建个人登录凭据，数据访问仍通过身份验证和归属校验。

登录后访问 `/api/v1/docs` 查看交互文档，`/api/v1/openapi.json` 获取 OpenAPI 3.0.3。使用说明、curl 示例与维护规则见 [API 文档](docs/api.md)。API 文档也需要鉴权。

```sh
npm run typecheck
npm test
npm run check:api
npm run build
npm run test:e2e
```

首次浏览器测试需要 `npx playwright install chromium`（Linux 上缺少系统库时使用 `npx playwright install --with-deps chromium`）。CI 执行类型检查、后端测试、OpenAPI 与路由一致性检查及浏览器测试；真实邮箱接入还需要自己的有效邮箱凭据与网络。

可选执行 `npm run test:mail`：使用 Docker / OpenSSL 自动搭建隔离的 GreenMail TLS 邮箱，验证两个账号、IMAP 标记 / 移动、SMTP 发信与附件。测试范围和环境见 [测试文档](docs/testing.md)。

目录：`server/` 后端；`web/` 前端与 PWA；`docs/` 接口和部署文档；`deploy/` Caddy 模板；`scripts/init.mjs` 初始化；`shared/api-contract.md` 开发协作契约。

## 平板与返回导航

可用宽度达到 1024 CSS 像素时，电脑和平板都显示邮箱导航、邮件列表、正文三栏；两条分隔线支持鼠标、触摸和键盘调整，刷新保留宽度。触屏分隔线提供 16 像素拖动区域，正文最小宽度为 320 像素；较窄竖屏自动切换布局。

返回手势优先关闭当前弹层或从邮件返回列表。写信时沿用草稿丢弃确认，取消会保留原草稿。独立 PWA 在根页首次返回会提示“再次返回退出应用”，短时间内再次返回才退出；普通浏览器标签页保留返回之前网页的行为。
