# MailNest v1 implementation contract

All endpoints under `/api/v1`. JSON success objects below; errors `{ error: { code: string, message: string } }` and meaningful HTTP status. Browser uses HttpOnly session cookie (credentials same-origin). Public routes only health and login. All others authenticated, including config and docs. First administrator bootstrapped using ADMIN_EMAIL/ADMIN_PASSWORD env. No public registration. Separate API tokens optionally support `Authorization: Bearer ...` for third-party clients.

## DTOs

User = { id: string, email: string, name: string }
Account = { id: string, name: string, email: string, color: string, provider: 'gmail' | 'imap', username: string, smtpUsername?: string, imap: {host:string,port:number,secure:boolean}, smtp:{host:string,port:number,secure:boolean}, status: 'connected'|'error'|'syncing'|'partial', lastSyncedAt: string|null, error: string|null, unread: number, folders: Folder[], authType:'oauth'|'password', hasSeparateSmtpCredentials:boolean }
Folder = { path:string, name:string, specialUse:string|null, selectable:boolean, kind:'inbox'|'sent'|'drafts'|'junk'|'trash'|'archive'|'important'|'custom' }
Address = { name: string, address: string }
MessageSummary = { id:string, accountId:string, folder:string, from:Address, to:Address[], cc:Address[], subject:string, preview:string, date:string, unread:boolean, starred:boolean, hasAttachments:boolean }
Message = MessageSummary & { text:string, html:string|null, messageId:string|null, bodyTruncated:boolean, attachments: {id:string, filename:string, contentType:string,size:number,contentId:string|null,inline:boolean}[] }

## Endpoints

- GET /health -> {status:'ok'} (public)
- POST /auth/login {email,password} -> {user:User}; session cookie
- GET /auth/me -> {user:User}
- POST /auth/logout -> {ok:true}; revoke cookie session
- POST /auth/password {currentPassword,newPassword} -> {ok:true}; password minimum 12 characters; revokes all sessions and API tokens, requires login again
- GET /config -> { googleConfigured:boolean, pushPublicKey:string|null, pollingInterval:number }
- GET /accounts -> {accounts:Account[]}; each account includes its cached actual folders (including empty folders and non-selectable containers); folders:[] before discovery; no remote IMAP request
- POST /accounts {name,email,color?,provider:'gmail'|'imap',username,password,imap:{host,port,secure},smtp:{host,port,secure},smtpUsername?,smtpPassword?} -> {account:Account} (201); color defaults to #6d5ce8; verify IMAP/SMTP before saving; passwords never returned; max20 accounts/user
- PATCH /accounts/:id {name?,color?,email?,username?,password?,imap?:{host,port,secure},smtp?:{host,port,secure},smtpUsername?:string|null,smtpPassword?:string|null} -> {account:Account,cacheReset:boolean}; at least one field, provider immutable; omitted/empty password keeps existing secret; omitted/empty smtpPassword keeps existing independent SMTP secret (when newly enabling separate SMTP without a secret, use the resulting IMAP password); smtpUsername:null and smtpPassword:null together restore shared IMAP credentials; OAuth accounts accept name/color only, reauthorize with Google flow. Metadata-only changes require no remote connection; changed connection/credentials verify IMAP and SMTP before atomic save, failure retains existing configuration. Identity changes (email or IMAP host ignoring case, or IMAP username) clear only this account's local mail/folder cache and schedule fresh synchronization, cacheReset:true; other changes preserve cache, account id unchanged, never delete remote mail. Internal cache generation prevents stale message ids from targeting another mailbox after identity changes.
- DELETE /accounts/:id -> {ok:true}; disconnect locally, not remove remote email
- GET /accounts/:id/folders -> {folders:Folder[]}; owner-scoped cached catalog, no remote connection; sync refreshes it; selectable:false identifies containers and QQ empty virtual parents without UID metadata; no estimated per-folder counts
- POST /accounts/:id/sync -> {ok:true}; schedule synchronization
- POST /sync {accountId?:string} -> {ok:true}; schedule one/all accounts
- GET /messages?accountId=&folder=INBOX|sent|drafts|junk|trash|archive|important|actualFolderPath&filter=all|unread|starred&q=&page=1&pageSize=30 -> {messages:MessageSummary[],total:number,page:number,pageSize:number}; logical folders resolved per mailbox by Special-Use / common names, all accounts if accountId omitted; with accountId an exact actual folder path takes priority over a logical alias; non-selectable containers return no messages; max100 selectablefolders/account, latest SYNC_MESSAGE_LIMIT summaries per folder plus flagged messages outside that window; cached searches match subject/from and previously loaded body, not full remote history; account unread uses remote INBOX unseen count
- GET /messages/:id -> {message:Message}; server SQLite body cache first, background prewarm of all starred and latest MAIL_CACHE_RECENT_COUNT merged owner records (across accounts/folders, ordered by date DESC,id); lazy BODYSTRUCTURE-based loading on a miss, max512KiB text / 2MiB HTML and bodyTruncated signals clipped body/metadata (max16 body parts / 100 attachment metadata entries); missing structure falls back to full MIME max30MiB; no persistent raw MIME or attachment binaries, does NOT auto mark read; UI shows successful body immediately, independent asynchronous PATCH on opening
- PATCH /messages/:id {unread?:boolean,starred?:boolean} -> {message:MessageSummary}; update remote IMAP then cached state
- POST /messages/:id/move {destination:'trash'|'archive'|'INBOX'} -> {ok:true}; move remote IMAP, update cache
- GET /messages/:id/attachments/:attachmentId -> on-demand binary attachment max30MiB, default application/octet-stream with attachment disposition; ?inline=true|1 returns image/png,jpeg,gif,webp,avif,bmp with matching MIME/inline disposition; false|0 means download, unsupported inline MIME returns 415 UNSUPPORTED_INLINE_TYPE; contentId maps cid: body images
- POST /messages/send {accountId:string,to:string,cc?:string,bcc?:string,subject:string,text:string,inReplyTo?:string,references?:string,attachments?:{filename:string,contentType:string,content:string}[]} -> {ok:true,messageId:string,warning?:string}; max20 attachments, content base64, total decoded attachments <=20 MiB; uses account SMTP, saves sent copy best-effort (Gmail saves automatically) and reports warning for partial SMTP recipient rejection or sent-copy failure; do not repeat delivery on warning
- GET /oauth/google/start -> {url:string}; authenticated, state bound to session/user, PKCE
- GET /oauth/google/callback?code=&state= -> redirect /?oauth=success or /?oauth=error&reason=...; callback session mandatory
- GET /events -> SSE; events named 'mail' with {accountId,count,notificationId,unreadCount,notification?:{subject:string,preview:string,from:{name:string,address:string}}}, 'sync' with {accountId,status:'syncing'|'connected'|'partial'|'error',unreadCount}, 'ready' with {unreadCount}; user-scoped, cookie auth; partial means some folders failed while other folders continue syncing, refresh account.error for sanitized reasons. unreadCount is this user's SUM(accounts.unread), the latest remote INBOX unseen counts, not cached message rows or duplicate label counts; zero with no unread/accounts.
- POST /push/subscriptions {endpoint:string,keys:{p256dh:string,auth:string}} -> {ok:true}
- DELETE /push/subscriptions {endpoint:string} -> {ok:true}
- POST /push/test {endpoint:string} -> {ok:true,accepted:true}; explicitly send one test to the current user's selected registered device, never broadcast. Accepted means Web Push provider accepted the request, not a delivery/display guarantee. Per-user cooldown of 15 seconds across devices, including failed sends; 429 PUSH_TEST_RATE_LIMIT includes Retry-After seconds. Missing and foreign endpoints both 404 PUSH_SUBSCRIPTION_NOT_FOUND; provider 404/410 removes only that subscription and returns 410 PUSH_SUBSCRIPTION_EXPIRED; other provider/network failures return 503 PUSH_DELIVERY_FAILED with safe generic text and retain subscription for retry; missing VAPID is 503 PUSH_NOT_CONFIGURED. Session writes require the same Origin guard; API tokens remain owner-scoped. No DNS/IP precheck, normal browser-provider HTTPS allowlist/TLS validation applies.

Push subscription endpoints retain the browser-provider HTTPS allowlist and key format validation. Registration performs no DNS/IP address filtering; network routing and resolution are delegated to the runtime/TUN, with normal HTTPS certificate verification. Re-registering the current user's endpoint updates its keys, including at the 20-device limit; another user's endpoint cannot be overwritten. Signed-in startup and foreground/online/controller-change recovery re-register existing granted subscriptions only when their applicationServerKey matches the configured VAPID public key; no automatic permission request or new subscription. Settings reports active only after server acknowledgement, and explicit enable replaces subscriptions made with an old VAPID key.

Normal and test Push notification JSON payloads are {title:string,body:string,url:string,tag:string,notificationId:string,unreadCount:number}; unreadCount uses the same owner-scoped INBOX total as SSE. Test notifications do not insert mail or change unread counts. Every payload carries a notificationId UUID; normal new-mail IDs match the corresponding SSE event, test IDs are independent but exercise the same worker display/deduplication pipeline. Both use urgency high, TTL 3600 seconds, explicit aes128gcm and an ID-derived 32-character topic: identical IDs may replace outstanding duplicates, different batches retain distinct topics. An established, unchanged INBOX UIDVALIDITY baseline triggers arrivals regardless of Seen status; initial import and UIDVALIDITY reset stay quiet. Foreground SSE and background Push share a worker notification queue and deduplicate successful displays by this ID; account tags use renotify to alert for subsequent batches. IndexedDB keeps only opaque IDs/timestamps for up to 7 days/128 entries (in-memory fallback), never messages or subscription secrets. History reads and writes each have a 500 ms deadline; errors or hanging storage permanently downgrade that worker to memory, and late callbacks cannot overwrite IDs or block following notifications. App worker registration observes existing installing/waiting workers and later updatefound events, bypasses the HTTP cache for updates and checks again on foreground/online recovery without forcing a page reload. Normal push acceptance/failure logs include safe status and hashed subscription identity, never raw endpoints/keys/provider errors. Badge support is optional and zero clears the badge; endpoint/key/raw provider error details are never returned from the test API.

MailEvent.notification is optional for compatibility and describes the latest newly arrived INBOX UID in the batch. Unicode code-point limits: subject 120, preview 200, from.name 80, from.address 254; strings normalize whitespace/control characters. A single latest message per batch prefetches its text/plain or text/html MIME body part before the INBOX transaction, retaining at most 16 KiB of decoded output without downloading attachments or setting Seen; this is not a strict network-byte limit including MIME/protocol overhead. Preview extraction has an 8-second deadline and falls back to an empty preview; missing BODYSTRUCTURE only permits a confirmed standalone text body, never a multipart source download. A bounded preview is retained in that message summary without caching source/full body. Normal Push title is subject (with a no-subject placeholder), body is sender plus plain-text preview (fallback '（无正文摘要）'), with '另有 N 封新邮件' for additional arrivals. SSE uses the same formatting and ID as Push. Legacy events/callers without details retain generic count text. The server durable delivery payload temporarily includes the bounded title/body until its one-hour expiration; logs and worker dedupe storage never contain this text. Notifications use a blue application icon and separate transparent monochrome Android badge; browser/OS attribution and layout remain platform-controlled.

SSE event 'change' is {accountId:string,action:'message-updated'|'message-moved'|'accounts-updated'|'message-sent',messageId?:string,message?:MessageSummary,unreadCount:number}. Successful flags updates include message and messageId; move includes messageId; ordinary account create/update/remove/order and successful send broadcast their corresponding action only to the same owner's signed-in streams. Google OAuth connection refreshes other devices through its scheduled sync event. Clients refresh loaded message ranges/accounts; merge changed summary metadata into an open message without reloading its HTML iframe, and return to the list if that message was moved. Mutations update unread total from a successful operation's current-row delta, then reconcile with remote complete INBOX STATUS; STATUS failure does not roll back a successful remote change, schedule a retry instead. No mutation event generates a new-mail system Push. New-mail delivery stages all currently registered owner subscriptions independently, with one shared batch ID and per-device dedupe; subscription authorization is per device, login alone does not grant notification permission. Frontend uses infinite scroll over the existing page/pageSize API (30 per batch), refreshes all loaded pages atomically and deduplicates IDs while retaining scroll; directory/filter/search changes restart loading.

- GET /tokens -> {tokens:{id:string,name:string,createdAt:string,lastUsedAt:string|null}[]}
- POST /tokens {name:string} -> {token:string,id:string}; plaintext only once
- DELETE /tokens/:id -> {ok:true}
- GET /openapi.json -> OpenAPI 3.0.3
- GET /docs -> interactive API docs, authenticated

## Environment

Dev Vite :5173 proxies /api -> :3001; production server serves `web/dist` on :3001. Server loads repo-root .env and validates secrets at startup. SQLite WAL in DATA_DIR. Persist only summaries and bounded body/attachment-metadata caches: MAIL_CACHE_RECENT_COUNT defaults to 100 (0–1000, per owner across accounts and folders; separate folder records count separately). Background warming after synchronization and starring reuses IMAP connections and yields to foreground work/sync, never changes Seen or sends arrival notifications. Cache hits bypass IMAP; bodies survive restart. Warm only structured MIME bodies; a missing structure uses the existing foreground fallback. MAIL_CACHE_MAX_MIB defaults to 256 (4–1024 MiB, instance-wide hard budget), prioritizing starred then recent targets then ordinary last-access LRU. Targets are exempt from TTL; MAIL_CACHE_TTL_DAYS defaults to 7 (1–365 days) for ordinary bodies, from last access. Budget may prevent all targets from remaining resident; misses refetch on demand, retries back off to avoid repeated warming of failures/evictions. No persistent raw MIME or attachment binaries; summary/config/index storage is separate from that byte limit. Upgrades clear legacy raw MIME, attachment binary, and incompatible body caches without deleting remote mail. AES-256-GCM encrypted stored mail credentials. Frontend sanitizes mail HTML in a sandbox iframe without scripts or same-origin permissions. Opening a message automatically loads CID body images on demand through controlled Data URLs and HTTP(S) external images, with no additional user action; external image requests use no-referrer. Browser checks verify actual image decoding. No caching authenticated API responses in SW. PWA SW supports push. No demo data automatically mixed with real inbox.

Private/loopback/link-local IMAP/SMTP hosts rejected by default to prevent SSRF from web-exposed connection forms; explicit ALLOW_PRIVATE_MAIL_HOSTS permits internal mail servers for self-hosted trusted deployments. TLS required: secure true implicit TLS, false STARTTLS required, certificate verification never disabled. APIs return ownership-scoped data for session or token user. Tokens cannot mint tokens or change password or start Google OAuth; those are session-only. Authentication/Google responses and all API responses use Cache-Control:no-store. Never expose stack traces, passwords/tokens, raw protocol auth logs.


PATCH /accounts/order {accountIds:string[]} -> {accounts:Account[]}; list all currently owned account IDs exactly once (max 20, [] for none). Save atomically; missing/duplicate/foreign/stale IDs return 400 ACCOUNT_ORDER_INVALID without partial changes. GET /accounts, navigation, settings and composer follow the saved server order across reload/devices; new accounts append, renaming preserves saved position. Existing auth/Origin checks apply.

POST /messages/send additionally accepts senderName?:string (max 80; reject CR/LF/NUL; trim). Omitted/blank defaults to selected account.name. Affects this message display name only; From address and SMTP credentials always use the owned accountId.

Normal new-mail pushes stage durable per-device deliveries within the INBOX cache transaction. One-hour fixed lifetime, at most 8 attempts with jittered exponential backoff, Retry-After and 4 concurrent senders; retry network/408/425/429/5xx only. Recover pending on server restart; never repeat provider-accepted IDs while retained. TTL is remaining lifetime, high/aes128gcm/topic remain unchanged, retry badge is current owner unread total. Revoked/changed subscription or deleted account cancels old tasks; 404/410 deletes only matching owner+subscription. Queue retains hashes rather than duplicate keys, expires records and caps at 4096. Explicit push test stays an immediate single attempt, not automatic outbox retries. Background/lockscreen operation uses system Web Push without a live page; platform permissions/force-stop/offline limits apply. Settings rechecks existing subscription on foreground/online without auto permission or subscription creation.
